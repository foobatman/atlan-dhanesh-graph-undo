# `undo` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `uv run undo <op_id>` reverses one recorded `delete_node`/`delete_edge` under rule B2, prints a JSONL report (one line per removed item), and refuses a second undo of the same op.

**Architecture:** A pure planner `domain/undo.py: plan_undo(UndoInputs) -> UndoPlan` holds every conflict rule. `api/undo.py: undo_op(store, op_id) -> UndoResult` validates the op, bulk-reads the inputs through repositories, calls the planner, and writes revives, new `contains` edges and the undo log in one `transaction`. `cli/undo.py` prints the report. Migration `0003_undo.sql` adds `undos` and `undo_items`.

**Tech Stack:** Python ≥ 3.11 stdlib (`sqlite3`, `json`, `dataclasses`), uv, pytest.

**Spec:** `docs/superpowers/specs/2026-11-19-undo-design.md`. Read its "Semantics" section before Task 2: the rule numbers 1, 2a–2e and the edge table are used below by name.

## Global Constraints

- Every command runs as `uv run …`. Commit directly on `main`, with no branches or worktrees.
- Runtime code is stdlib only. No new fields on nodes or edges.
- Layers: `cli → api → db → domain`. SQL lives only in `db/`, and `tests/test_layers.py` must stay green. `cli` may import only `api` and `domain`.
- Id lists go to SQL as one `json_each(?)` parameter, so each repo call is a constant number of statements.
- Error text is `str(e) == f"{op_id} {code}: {message}"` (existing `OpError`).
- The report is JSONL on stdout: node lines first, sorted by `(qualified_name, id)`, then edge lines, sorted by `id`. Each line is `canonical(obj) + "\n"`. There is no summary line on stdout.
- Outcomes: nodes are `restored|skipped`; edges are `restored|merged|skipped`. `reason_code` and `reason` appear only on merged and skipped items.
- README is updated in the same commit as the change it describes (CLAUDE.md).
- Crash handling (`CRASH_AFTER`) is out of scope. One undo is one transaction.

## Review Focus

1. **Undo order across two deletes:** E6's delete is undone first (T′ comes back and holds T's name), then op-0001. T is skipped as `name_held`, and T's free-named columns reattach under T′. Test `test_undo_e6_then_op0001` (Task 4).
2. **Apply after undo:** a later `apply` of a human `add_node` with a restored name gets `name_taken`, and a `delete_node` of a restored node removes only live rows. Test `test_apply_after_undo` (Task 3).
3. **Determinism:** two fresh load+apply+undo runs print byte-identical stdout. Test `test_report_deterministic` (Task 4).
4. **Db not migrated to 3:** `undo` exits 1 with the apply-style "needs migrations" message and writes nothing. Test `test_cli_pending_migration` (Task 4).
5. **Bad `op_id` input** (`op-1`, `foo`): exits 1 with `malformed`, and the db is unchanged. Test `test_cli_malformed_op_id` (Task 4).

### Task 2: Pure planner (all conflict rules)

**Files:**
- Create: `src/graph_undo/domain/undo.py`
- Test: `tests/undo/test_planner.py` (no db, only `Node`/`Edge` values)

**Interfaces:**
- Consumes: `Node`, `Edge` (`domain/model.py`) and `canonical` (`domain/ops.py`).
- Produces:

```python
@dataclass(frozen=True)
class UndoInputs:
    op_id: str
    op: str                                   # 'delete_node' | 'delete_edge'
    root_id: str | None                       # delete_node root; None for delete_edge
    removed_nodes: dict[str, Node]            # N, by id (dead rows)
    removed_edges: list[Edge]                 # E
    others: dict[str, Node]                   # every endpoint of E outside N, live or dead, by id
    holders: dict[str, Node]                  # qualified_name -> live node holding it (names of N and of dead `others`)
    creators: dict[str, tuple[str, str]]      # holder id -> (op_id, actor_kind); absent = seed
    live_triples: set[tuple[str, str, str]]   # live (from, to, type) among E's triples
    live_parents: dict[str, Edge]             # child id -> its live contains edge (children of contains edges in E)

@dataclass(frozen=True)
class NodeOutcome:
    node: Node; outcome: str; parent_id: str | None = None
    reason_code: str | None = None; reason: str | None = None

@dataclass(frozen=True)
class EdgeOutcome:
    edge: Edge; outcome: str; new_from_id: str | None = None      # merged: holder id
    reason_code: str | None = None; reason: str | None = None

@dataclass(frozen=True)
class UndoPlan:
    op_id: str; op: str
    nodes: list[NodeOutcome]                  # top-down order (write order)
    edges: list[EdgeOutcome]                  # by edge id

def plan_undo(inp: UndoInputs) -> UndoPlan
def report_lines(plan: UndoPlan, new_edge_ids: dict[int, int]) -> list[str]   # original edge id -> new id
```
